# JARVIS 5.14.0 — Professional HUD

## Что исправлено
- `versionCode` повышен с 17 до 18, `versionName` — `5.14.0-professional-hud`. Application ID и release signing key сохранены, поэтому APK устанавливается поверх предыдущей версии как обновление при использовании того же ключа.
- Единый HUD-стиль для всех интерактивных кнопок: одинаковая рамка, тёмная панель, радиус, типографика и автоподгонка текста.
- Перестроен главный экран на адаптивную вертикальную компоновку вместо набора жёстких высот, из-за которых текст и кнопки могли накладываться друг на друга.
- Полноэкранный immersive-режим повторно применяется при возвращении в Activity.
- Нажатие на ядро и `ГОВОРИТЬ` запускают реальный `SpeechRecognizer`; при проблеме с экземпляром распознавателя он пересоздаётся.
- Фоновый вызов «Джарвис» больше не конкурирует за микрофон с MainActivity: wake-word сервис освобождает микрофон перед открытием интерфейса и возобновляется после закрытия Activity, если режим включён.
- Добавлен переход к настройкам исключения JARVIS из оптимизации батареи.
- Реальный таймер теперь создаётся через `AlarmManager`, а не только через UI Clock. Он переживает закрытие процесса JARVIS. При необходимости Android запрашивает разрешение на точные будильники.
- Таймер можно отменить командой `отмени таймер` / `отключи таймер`.
- Уведомление таймера имеет высокий приоритет, звук и вибрацию.
- Погода продолжает получать текущие данные через Open-Meteo; ответ сразу передаётся в TTS, а не берётся из Википедии.
- Исправлен подбор русской TTS Voice: используется `Voice.QUALITY_NORMAL`, совместимый с текущим Android SDK.
- Добавлена проверка наличия итогового release APK в GitHub Actions.

## Проверка
В этом окружении Gradle CLI не установлен, поэтому локально здесь невозможно выполнить `:app:assembleRelease`. GitHub Actions workflow проекта настроен на:

`gradle --no-daemon --stacktrace :app:assembleRelease`

и после сборки проверяет наличие непустого `app/build/outputs/apk/release/app-release.apk`.
